## 2. 已定后端数据形状（另 PR）

扩展 `release_year_stats`（按年 + `All Time`）：

| 媒体 | 新增列（语义） | 年份口径 |
| --- | --- | --- |
| 专辑 | **总数**、**已听** | 专辑发行日 |
| 图书 | **总数**、**已读**、**在读** | 书出版日 |

约定：

- **不提供**年统计下的「在听／想听／想读」列；UI 只渲染上述字段。
- **「完成进度」仍只算影视片长**；专辑、图书不并入。
- 原型 mock 字段名：`total_albums` / `listened_albums` / `total_books` / `read_books` / `reading_books`（最终列名以后端 PR 为准，前端再对齐 `Summary`）。

前端落地时：`getCachedReleaseYearStats` 已读到的同一行即可驱动年份切换，**不必再并行 `get_media_stats`**（除非详情页／目录另有需求）。

状态用语（仅展示后端有的）：

- 音乐：**已听**（+ 总数）
- 图书：**已读**、**在读**（+ 总数）
- 量词：部／张／本
- 空态：弱化 +「暂无收录」

## 3. 三个前端方案（按已定字段）

### 方案 A · 四格并列

- 标题：四类总计 + **完成进度（影视）**
- 总览 2×2：电影／电视照旧；音乐＝总数＋已听；图书＝总数＋已读＋在读
- **优点**：四类对等，年份切换同一数据源
- **缺点**：图书为 0 仍占大卡；音乐单列「已听」相对电视三态偏空（可用「共 N 张」补）

### 方案 B · 主次两层

- 标题：保持电影／电视／完成进度；脚注带出音书总数与已听
- 主层影视大卡；次层「声音与文字」紧凑双卡（字段同上）
- **优点**：改动面小、视觉延续强
- **缺点**：音书叙事偏次

### 方案 C · 密度行（推荐）

- 标题：四类短总计 + 影视完成进度
- 每类一行：音乐「已听｜总计」；图书「已读｜在读」；影视保持多态
- **优点**：字段多少都能自然伸缩；空态成本低；手机好扫
- **缺点**：与现网大卡略有落差

---

## 4. 推荐

**仍推荐方案 C。**

1. 后端只给音书少数列，行式布局比等权大卡更贴合「有什么画什么」。  
2. 完成进度与音书解耦后，标题区五格（四类＋进度）在 C／A 都清晰；C 总览更不易因图书 0 显得空洞。  
3. 年份切换无额外 RPC，与已定视图改法一致。

影视永远主视觉 → 退选 **B**。
