# 内容管理工作台

唯一管理入口为 `/manage`；旧 `/admin` 路由不存在，访问返回 404。账号安全继续使用 `/settings`。两者放在路由组 `app/(admin)/` 下，共用带侧栏的外框与身份检查，网址不含组名。

## 操作方式

- 桌面侧栏、手机分类选择器提供电影、电视节目、人物、系列、类型、地区、语言与报告入口。季与单集不再单独列出，在所属电视节目的工作台中编辑；`/manage?type=tv_season` 等列表地址仍可直接访问。
- 列表每页 25 项，切换分类及返回列表恢复同一浏览器会话中的搜索和页码。搜索同时匹配标题与副标题，`%`、`_` 按字面匹配；可按观看状态筛选（「在看」只适用于电视节目与季），按上映日期（电视节目与季为最近播出）、标题或评分排序（季不提供评分排序）。状态与评分来自 `v_manage_media_order`，口径与列表显示一致。电视节目每行显示季数与总集数，并可直接新增下一季。
- 编辑电视节目、季或单集时进入同一个工作台：右侧「剧集结构」栏与左侧导航同高并跟随滚动，列出全部季与展开季的单集（分块读取，单季上千集也完整显示），点击即可切换编辑对象。超过 8 季时改用下拉选择季，超过 20 集时可输入集号跳转；窄屏时结构栏收成表单上方的卡片，季从底部面板选择。
- 新增季与单集只在结构栏中进行，弹窗预填上级与下一个编号；单集另按最近两集的播出间隔推算日期、沿用上一集时长。勾选「保存后继续新增」时留在当前页连续录入，否则打开新条目。特别篇支持编号 0，最终由数据库检查上级类型及编号唯一性。
- 类型、地区、语言以卡片网格显示；人物、系列的详情页左侧为资料表单，右侧为关联作品。报告概览显示待处理与已清理数量；账号安全显示每个凭证的最后使用日期。
- 关联选择器一次显示最多 20 个搜索结果。人物、类型、地区、语言、系列的新名称随媒体表单一起保存；移除标签只解除当前作品关联。
- 演员和导演分别选择，同一人物可有多个角色；演员列表支持上移调整顺序。
- 人物、系列有独立详情；类型、地区既有快速编辑弹窗，也有展示关联作品的详情页。
- 详情页的关联作品按电影、电视节目、季、单集分组，组内按上映日期倒序，每页 25 部；卡片显示封面、副标题、上映日期、片长及季集所属节目。人物同一作品只列一次，职务合并为「导演、演员」并附角色名。系列仍按顺序号排列。
- 系列内可添加作品、独立修改顺序及移除成员。顺序较小的优先，同顺序按作品 ID 排列。
- 编辑表单显示未保存状态。刷新、关闭、站内链接跳转及浏览器后退有未保存提示，每次离开只询问一次。为拦截后退而压入的同地址历史记录在离开时被替换，不会让后退多按一次。
- 「数据检查 → 报告」汇总十份报告：未填别名的人物、未填角色名、疑似名字错误、疑似重复人物、未关联作品的人物、演职员顺序异常、资料不完整、季集结构、观看记录矛盾、闲置关联资料。每行链接到可修正该问题的编辑页；「疑似名字错误」「疑似重复人物」只按写法规则判断，需逐一确认。
- 未关联作品的人物、闲置关联资料可批量删除，须输入当前数量确认；服务端再核对数量，数据库删除时重新检查未被引用。
- 永久删除从保存按钮旁的删除按钮打开确认弹窗，必须输入完整标题或名称；删除电视节目／季显示下属计数，删除关联资料保留影视与观看记录。人物如仍作为专辑艺术家被引用，会由外键拒绝删除并提示先解除关联。

## 权限与发布

每个 Server Action 独立调用 `requireOwner()`；数据库通过 `site_owner` 和 RLS 再校验站长。没有在客户端暴露运维密钥，也没有增加认证绕过开关。

管理工作台的结构增量已于 2026-09-11 应用到生产，并已包含在基线迁移 `20260925000000_initial_schema.sql` 中。新增的 `manage_save_media(jsonb)` 使用调用者权限，在同一事务中调用原有媒体保存函数并维护系列关联。匿名角色没有执行权限；原 `admin_save_media` 保留供已有应用版本使用，其命名与删除 `/admin` 网页路由无关。

回滚应用时可保留数据库扩展，它与旧版兼容。如果需要完全撤回数据库扩展，先回滚依赖 `manage_save_media` 的应用，再删除该函数、系列两张表的六条 `Owner` 策略，并撤销这两张表向 `authenticated` 的 INSERT、UPDATE、DELETE 权限。不要删除系列数据或原有只读策略。

## 验证边界

- 单元／组件：关联选择、父级 ID、排序移除、错误恢复及原有输入校验。
- 数据库：`supabase/tests/manage_media_order.test.sql` 验证管理列表的排序日期、观看状态、评分与别名；`supabase/tests/manage_reports.test.sql` 验证各报告视图的判断条件、匿名不可读及批量删除权限；`supabase/tests/admin_schema.test.sql` 验证站长／非站长权限、原子保存、级联删除与系列顺序保留。可在本地 Supabase 运行 `supabase test db`。
- E2E：`e2e/admin-management.spec.ts` 包含八类 CRUD；仅允许本地 Supabase，并需要本地 service-role key。禁止用生产库跑写入测试。
- 本次本地缺少已登录的站长会话：真实环境验证匿名拦截与八类只读查询；视觉检查使用独立示例内容，不代表已完成真实浏览器写入测试。
