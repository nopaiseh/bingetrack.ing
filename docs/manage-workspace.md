# 内容管理工作台

管理入口是 `/manage`，账号安全在 `/settings`。两者位于路由组 `app/(admin)/`，共用带侧栏的外框和身份检查，网址里不含组名。旧的 `/admin` 路由已删除，访问返回 404。

## 概览页

登录后进入 `/manage`：

- **全局搜索**：同时搜索电影、电视节目、季和单集的标题与副标题，最多 40 条，可以按类型缩小范围。
- **待录入**：最近 30 天内有播出的电视节目。按最近两集的间隔推算下一集，已到期的排在前面，可以直接新增下一集。
- **报告摘要**：各份数据检查报告的待处理数量。

数据库没有更新时间字段，所以没有「最近编辑」。

## 导航

- 桌面侧栏和手机上的分类下拉框提供：概览、电影、电视节目、人物、系列、类型、地区、语言、报告、账号安全。季和单集不单独列出，在所属电视节目的工作台里编辑；`/manage?type=tv_season` 这类地址仍可直接访问。
- 桌面侧栏可以收起成 64px 的图标栏。偏好存在 `admin-nav` Cookie 中，服务端首屏就按对应宽度渲染。
- 侧栏和手机顶部都有「刷新缓存」按钮，用于直接在 Supabase 改过数据之后。它会让全站公开缓存失效，见 [缓存说明](caching.md)。

## 列表

- 每页 25 项。切换分类和从详情返回时，恢复同一浏览器会话里的搜索词和页码。
- 搜索同时匹配标题与副标题，`%` 和 `_` 按字面匹配。
- 可按观看状态筛选（「在看」只适用于电视节目和季）；可按上映日期、标题或评分排序（季没有评分排序）。电视节目与季的日期取最近一集的播出日期。
- 状态、评分和排序日期来自视图 `v_manage_media_order`，与列表显示的口径一致；视图缺失时退回按条目自身的上映日期排序。
- 电视节目每行显示季数与总集数，可以直接新增下一季。

## 电视节目工作台

编辑电视节目、季或单集时进入同一个工作台：

- 右侧「剧集结构」栏与左侧导航等高，跟随滚动，列出全部季和展开季的单集，点击即可切换编辑对象。单集分块读取，单季上千集也能完整显示。
- 超过 8 季时改用下拉框选择季；超过 20 集时可以输入集号跳转。
- 窄屏时结构栏收成表单上方的卡片，季从底部面板选择。
- 新增季和单集只在结构栏里进行。弹窗预填上级和下一个编号；单集还会按最近两集的播出间隔推算日期，并沿用上一集的时长。
- 勾选「保存后继续新增」时留在当前页连续录入，否则打开新条目。
- 特别篇可以用编号 0。上级类型和编号唯一性最终由数据库检查。

## 编辑表单

- 电影和单集没有单独的观看状态选项：填了评分就是看过，留空就是没看过。服务端按同一规则保存，忽略提交上来的状态。
- 关联选择器一次最多显示 20 个搜索结果。人物、类型、地区、语言、系列的新名称随媒体表单一起保存；移除标签只解除与当前作品的关联，不删除词条本身。
- 演员和导演分开选择，同一人物可以有多个职务；演员可以填写角色名，并可上移调整顺序。
- 表单会显示未保存状态。刷新、关闭标签页、站内跳转和浏览器后退时，如果有未保存的修改会提示一次。
- 封面只接受 `https://image.tmdb.org/t/p/` 开头的地址，与 CSP 的图片来源一致。图片由浏览器直接向 TMDB 请求，`lib/tmdb-image-loader.ts` 按显示宽度换成最接近的尺寸档位，不经过 Vercel 图片优化。

## 关联资料

- 人物和系列有独立的详情页：左侧是资料表单，右侧是关联作品。类型、地区既可以用快速编辑弹窗，也有展示关联作品的详情页。类型、地区、语言的列表以卡片网格显示。
- 关联作品按电影、电视节目、季、单集分组，组内按上映日期倒序，每页 25 部。人物在同一作品里只列一次，职务合并显示（如「导演、演员」）并附角色名。
- 系列内的作品按顺序号排列，顺序号相同时按作品 ID。可以添加作品、单独修改顺序和移除成员。
- 同名人物用别名区分。

## 数据检查报告

「数据检查 → 报告」包含十份报告：未填别名的人物、未填角色名、疑似名字错误、疑似重复人物、未关联作品的人物、演职员顺序异常、资料不完整、季集结构、观看记录矛盾、闲置关联资料。每一行都链接到能修正该问题的编辑页。

- 「疑似名字错误」和「疑似重复人物」只按写法规则判断，需要逐条确认。
- 「疑似重复人物」按组显示，可以：
  - **合并**：选定保留的人物后调用 `manage_merge_people`，一次完成。演职关联并入保留者；同作品同职务只补角色名、取较前的番位；保留者没有别名时沿用被合并者的别名；最后删除被合并者。仍是专辑艺术家的人物会被拒绝合并。
  - **标记「不是同一人」**：写入 `people_distinct_pairs`，该组不再出现。任一人物被删除时，相关记录一并清除。
- 「观看记录矛盾」只会列出直接改库造成的旧数据，因为表单已经不能产生这种矛盾。
- 未关联作品的人物和闲置关联资料可以批量删除：需要输入当前数量确认，服务端会再核对一次数量，数据库删除时也会重新检查是否仍被引用。

## 删除

永久删除从保存按钮旁的删除按钮进入确认弹窗，必须输入完整的标题或名称。

- 删除电视节目会同时删除它的季、集、观看记录和评分；删除季会同时删除该季的集。弹窗会显示下属的数量。
- 删除关联资料（人物、类型等）只移除词条和关联，不影响影视条目和观看记录。
- 人物如果仍被专辑作为艺术家引用，外键会拒绝删除，并提示先解除关联。
- 删除后回到所属列表；季和单集回到电视节目列表。

## 权限

每个 Server Action 都会先调用 `requireOwner()`；数据库再通过 `site_owner` 和 RLS 校验一次。客户端没有任何运维密钥，也没有认证绕过开关。认证流程见 [单人管理与 Passkey](single-owner-admin.md)。

保存用的 `manage_save_media(jsonb)` 以调用者权限运行，在同一个事务里保存媒体并维护系列关联；匿名角色没有执行权限。旧函数 `admin_save_media` 保留给已有的应用版本使用，它的名字与已删除的 `/admin` 网页路由无关。

## 测试

- 单元／组件测试（`tests/manage-*.test.ts(x)`、`tests/admin-*.test.ts`）：表单解析、关联选择、快速新增、未保存提示、报告操作、缓存失效范围等。
- 数据库测试：
  - `supabase/tests/manage_media_order.test.sql`：管理列表的排序日期、状态、评分与别名。
  - `supabase/tests/manage_reports.test.sql`：各报告视图的判断条件、匿名不可读和批量删除权限。
  - `supabase/tests/admin_schema.test.sql`：站长与非站长权限、原子保存、级联删除、系列顺序。
- 浏览器测试：`e2e/admin-management.spec.ts` 覆盖八类资料的增删改，`e2e/admin-access.spec.ts` 覆盖未登录拦截。管理测试只允许对本地 Supabase 运行，并需要本地 service-role key，禁止用生产库。
