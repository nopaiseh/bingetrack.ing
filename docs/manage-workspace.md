# 内容管理工作台

唯一管理入口为 `/manage`；旧 `/admin` 路由不存在，访问返回 404。账号安全继续使用 `/settings`。

## 操作方式

- 桌面侧栏、手机分类选择器提供电影、电视剧、剧季、剧集、人物、系列、类型、地区八个入口。
- 列表每页 25 项，切换分类及返回列表恢复同一浏览器会话中的搜索和页码。
- 电视剧进入下属剧季、剧季进入下属剧集，可直接新增并预填上级及下一个编号；特别篇支持编号 0，最终由数据库检查上级类型及编号唯一性。
- 关联选择器一次显示最多 20 个搜索结果。人物、类型、地区、语言、系列的新名称随媒体表单一起保存；移除标签只解除当前作品关联。
- 演员和导演分别选择，同一人物可有多个角色；演员列表支持上移调整顺序。
- 人物、系列有独立详情；类型、地区既有快速编辑弹窗，也有展示关联作品的详情页。
- 系列内可添加作品、独立修改顺序及移除成员。顺序较小的优先，同顺序按作品 ID 排列。
- 编辑表单显示未保存状态。刷新、关闭及站内链接跳转有未保存提示。
- 永久删除必须输入完整标题或名称；删除电视剧／剧季显示下属计数，删除关联资料保留影视与观看记录。人物如仍作为专辑艺术家被引用，会由外键拒绝删除并提示先解除关联。

## 权限与发布

每个 Server Action 独立调用 `requireOwner()`；数据库通过 `site_owner` 和 RLS 再校验站长。没有在客户端暴露运维密钥，也没有增加认证绕过开关。

`supabase/archive/manage-catalog.sql` 已于 2026-09-11 应用到生产，并同步至 `current_schema.sql`。新增的 `manage_save_media(jsonb)` 使用调用者权限，在同一事务中调用原有媒体保存函数并维护系列关联。匿名角色没有执行权限；原 `admin_save_media` 保留供已有应用版本使用，其命名与删除 `/admin` 网页路由无关。

回滚应用时可保留数据库扩展，它与旧版兼容。如果需要完全撤回数据库扩展，先回滚依赖 `manage_save_media` 的应用，再删除该函数、系列两张表的六条 `Owner` 策略，并撤销这两张表向 `authenticated` 的 INSERT、UPDATE、DELETE 权限。不要删除系列数据或原有只读策略。

## 验证边界

- 单元／组件：关联选择、父级 ID、排序移除、错误恢复及原有输入校验。
- 数据库：`supabase/tests/admin_schema.test.sql` 验证站长／非站长权限、原子保存、级联删除与系列顺序保留。可在本地 Supabase 运行 `supabase test db`。
- E2E：`e2e/admin-management.spec.ts` 包含八类 CRUD；仅允许本地 Supabase，并需要本地 service-role key。禁止用生产库跑写入测试。
- 本次本地缺少已登录的站长会话：真实环境验证匿名拦截与八类只读查询；视觉检查使用独立示例内容，不代表已完成真实浏览器写入测试。
